# مقدمة المشتريات وSRM

وحدة **المشتريات وعلاقات الموردين (SRM & Procurement)** في Drixal ERP تدير مسار التوريد من الاحتياج الداخلي إلى السداد: الموردون، طلبات الشراء، طلبات عروض الأسعار والمناقصات، عروض الموردين، أوامر الشراء، فواتير الحسابات الدائنة والمستندات المرتبطة، المدفوعات، والمردودات.

بدون هذه الوحدة تبقى طلبات الشراء في جداول وبريد. داخل Drixal يصبح كل خطوة سجلًا متصلًا يسلّم للمستند التالي في مسار المشتريات.

## ماذا تفعل الوحدة لأعمالك

- تسجّل الموردين وتدير الحظر وقائمة الأسعار والرصيد الافتتاحي والفواتير والمدفوعات من **Supplier** و**360**
- تلتقط الاحتياج كـ **PurchaseRequisition** ثم تحوّله إلى **QuoteRequest** أو **Bid**
- تجمع عروض الموردين عبر **SupplierQuote** حتى القبول والتحويل إلى أمر شراء
- تصدر **PurchaseOrder** ثم **InvoiceAP** (وReturn / Credit / Debit) وتسجّل **PaymentAP** / **RefundAP**
- تعطي الإدارة **Dashboard** للقراءة فقط بمؤشرات الالتزام والذمم الدائنة

## مسار المشتريات

الترتيب ليس معالجًا مدمجًا؛ يفرضه الاعتماد والاستخدام اليومي:

```text
PurchaseRequisition
  ├── QuoteRequest (RFQ)
  │     └── SupplierQuote
  │           └── PurchaseOrder
  └── Bid
        └── SupplierQuote (ترسية)
              └── PurchaseOrder
                    └── InvoiceAP
                          ├── ReturnInvoiceAP / CreditNoteAP / DebitNoteAP
                          └── PaymentAP / RefundAP
```

| الخطوة | السجل | الغرض |
|---|---|---|
| 1 | **PurchaseRequisition** | طلب شراء داخلي؛ Submit ثم Convert to QuoteRequest أو Bid |
| 2 | **QuoteRequest** / **Bid** | طلب عرض لمورد واحد، أو مناقصة لعدة موردين |
| 3 | **SupplierQuote** | عرض المورد؛ Accept / Reject ثم Convert to PO |
| 4 | **PurchaseOrder** | التزام الشراء؛ Send، Accept، Create Invoice، Add Payment |
| 5 | **InvoiceAP** | فاتورة مشتريات؛ Post، Add Payment، Return / Credit / Debit |
| 6 | **PaymentAP** / **RefundAP** | مدفوعات ومردودات الموردين (أغلفة SRM فوق FIN / SHRD) |

:::note[أمر شراء العميل ليس في SRM]
**CustomerPO** (أمر شراء العميل) موثّق في [CRM](/docs/crm/customer-po) وليس ضمن أدلة المشتريات.
:::

## أهداف الوحدة في المنشأة

- حوكمة الإنفاق عبر دورة طلب ← عرض ← أمر ← فاتورة ← دفع
- سجل موحد للموردين مع إجراءات الحظر والتسعير والرصيد
- تسريع التحويل من طلب الشراء إلى RFQ أو مناقصة ثم أمر شراء
- تكامل التكاليف مع المشاريع (حقول المحفظة/المشروع على الأوامر) والقيود المالية عبر FIN عند الترحيل
- مرفقات وعقود داخل كل معاملة عبر إطار المرفقات المشترك (DMS)

## من يستخدم هذا القسم

| الدور | الاستخدام اليومي |
|---|---|
| مدير / أخصائي مشتريات | طلبات، RFQ، مناقصات، عروض، أوامر شراء |
| أمين مستودع / عمليات | متابعة أوامر الشراء والاستلام التشغيلي المرتبط |
| محاسب موردين (AP) | InvoiceAP، الإشعارات، PaymentAP، RefundAP |
| الإدارة | مؤشرات اللوحة والالتزام والذمم الدائنة |

## كيف يُنظَّم دليل المشتريات

1. المقدمة واللوحة
2. الموردون
3. طلب الشراء، طلب العرض، المناقصة، عرض المورد
4. أمر الشراء وفاتورة المشتريات
5. المرتجع والإشعارات والمدفوعات والمردودات
6. المصطلحات

## أفضل الممارسات

:::tip[اتبع السلسلة قبل اختصار الطريق]
Submit الطلب، أرسل RFQ أو انشر المناقصة، اقبل العرض، ثم أصدر أمر الشراء والفاتورة. تخطّي الخطوات يكسر الروابط وتبويبات 360.
:::

:::warning[اللوحة للقراءة فقط]
لوحة المشتريات لا تنشئ ولا تعدّل سجلات. افتح صفحات الكيانات للإنشاء والتعديل.
:::

اضغط **المساعدة** من ترويسة التطبيق وأنت على صفحة SRM لفتح الدليل المطابق.
:::
