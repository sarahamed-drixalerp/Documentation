# الوثائق

**الوثيقة (Document)** هي سجل ضبط وثائق المشروع في Drixal ERP: بيانات وصفية، مرفقات، ومسار مراجعة متعدد المراحل — أو وضع **رفع فقط (Upload Only)** بدون سير عمل.

**المسار:** القائمة الجانبية ← إدارة الوثائق ← الوثائق  
**الصفحات:** `/Entities/DMS/Document` · `/Entities/DMS/Document/new` · `/Entities/DMS/Document/{رقم}`  
استعلامات مفيدة: `?tab=workflow` · `?tab=logs` · `?attachmentsTab=supporting` · `?LinkedDocumentId=`

صفحة السجل مساحة عمل (تفاصيل ومرفقات، سير عمل، سجلات).

## ماذا تفعل هذه الشاشة

- تربط الملف بمشروع DMS ونوع وثيقة ومقاول عند الحاجة
- تدير المرفق الرئيسي والمرفقات الداعمة
- تشغّل سير عمل مراجعة بمراجع حالي وتقدّم مراحل
- تدعم الوثائق المرحَّلة (Migrated) ووضع Upload Only وربط وثيقة سابقة (LinkedDocument)

## قائمة الوثائق

عروض: **قائمة** و**بطاقات**.

### الأعمدة

| العمود | المعنى |
|---|---|
| **الاسم (Document Title)** | `name` مع شارات **Migrated** / **Upload Only** ونوع الوثيقة كعنوان فرعي |
| **المراجع الحالي (currentReviewer)** | من بانتظار إجراءه |
| **المقاول (Contractor)** | المقاول المرتبط |
| **مشروع DMS (dmsProject)** | المشروع |
| **تقدّم سير العمل (workflowProgress)** | تقدّم المراحل |
| **إجراءات** | خطوة سير العمل، تنزيل أحدث نسخة، حذف |

### التصفية

| التصفية | الاستخدام |
|---|---|
| **Name** | بحث بالاسم |
| **Contractor** | مقاول |
| **DMSProject** | مشروع DMS |
| **DocumentType** | نوع الوثيقة |
| **Source** | الكل · مرحَّل (Migrated) · نظام جديد (NewSystem) |
| **Workflow kind** | الكل · رفع فقط (UploadOnly) · مع سير عمل (WithWorkflow) |
| **Pending On** | معلّق لدى مستخدم (`PendingOnUsrIds`) |

## إنشاء وثيقة

**الصفحة:** `/Entities/DMS/Document/new`

### الحقول الإلزامية

| الحقل | ملاحظات |
|---|---|
| **نوع الوثيقة (DocumentType)** | يحدد القواعد: ملفات، امتدادات، تخصصات، سير عمل أو رفع فقط |
| **الرمز / الاسم (Code / Name)** | مع **بادئة (Prefix)** اختيارية من بادئات النوع |
| **مشروع DMS (DMSProject)** | ربط المشروع |
| **EntityType / EntityStatus** | نوع وحالة الكيان في النموذج |
| **سرية البيانات (DataConfidentiality)** | تصنيف السرية عند تفعيله في النموذج |

إن كان النوع **متعدد التخصصات** يجب اختيار **تخصص فني واحد على الأقل** (`isTechnical`).

### الحقول الاختيارية

| الحقل | ملاحظات |
|---|---|
| **المقاول (Contractor)** | ربط المقاول |
| **nameAr** | الاسم بالعربية |
| **description / descriptionAr** | أوصاف |
| **LinkedDocument** | وثيقة سابقة عبر الاستعلام؛ يقفل النوع والبادئة والمقاول والمشروع والتخصصات |

## تبويبات السجل

| التبويب | الغرض |
|---|---|
| **التفاصيل والمرفقات (Details & Attachments)** | الهوية + المرفق الرئيسي (`Document`) والمرفقات الداعمة (`DocumentSupporting`) |
| **سير العمل (Workflow)** | مراحل المراجعة؛ **مخفي** للرفع فقط وللسجلات الجديدة غير المرسلة |
| **السجلات (Logs)** | أثر التغييرات |

## دورة الحياة وسير العمل

| الوضع | السلوك |
|---|---|
| **مسودة / معلّق (Draft / Pending)** | قابل للتعديل؛ **إرسال الوثيقة (Submit)** يتطلب مرفقًا واحدًا على الأقل ثم يُقفل للمراجعة (ما لم يكن Upload Only) |
| **تغيير المرحلة** | تغيير الحالة ← حفظ / **إرسال للمرحلة التالية (Submit & Next)**؛ **تعليق إلزامي** للتقدّم |
| **إرسال خطاب للمالك (Send Letter to Owner)** | خيار في حوار سير العمل يُرسل مع عنصر العمل |
| **معتمد (Approved)** | لافتات لحالات مثل Approved / Approved with Comments / Code-A / Code-B وما يطابقها عربيًا |
| **مرفوض (Rejected)** | لافتات Rejected / Code-C / Code-D؛ المقاول يمكنه **إعادة فتح كمسودة (Reopen as Draft)** |
| **رفع فقط (Upload Only)** | بلا سير عمل وبلا إرسال للمراجعة؛ شارة دائمة؛ الترويسة غالبًا للقراءة بعد الإنشاء |
| **مرحَّل (Migrated)** | شارة عند وجود `oldKey` / `OldKey` |
| **LinkedDocument** | نسخ/قفل النوع والمقاول والمشروع من الوثيقة السابقة |

### خطوات الإرسال (مع سير عمل)

1. أنشئ الوثيقة كمسودة مع النوع والمشروع والرمز
2. ارفع مرفقًا رئيسيًا واحدًا على الأقل
3. إن لزم، اختر التخصصات الفنية للنوع متعدد التخصصات
4. اضغط **إرسال الوثيقة**
5. في تبويب سير العمل غيّر الحالة مع تعليق عند **إرسال للمرحلة التالية**
6. استخدم **إرسال خطاب للمالك** عند الحاجة
7. عند الرفض (بوابة المقاول) استخدم **إعادة فتح كمسودة** ثم صحّح وأعد الإرسال

## أخطاء شائعة

- إرسال بدون مرفق
- نسيان التخصصات للتعدد التخصصي
- تخطّي التعليق عند Submit & Next
- محاولة تعديل الترويسة بعد خروج المسودة (غير مسودة / رفع فقط → أجزاء للقراءة فقط)

## أفضل الممارسات

:::tip[ارفع المرفق قبل الإرسال]
زر الإرسال يرفض المسار بدون ملف. جهّز النسخة النهائية أولًا.
:::

:::warning[التعليق مطلوب للتقدّم في المراحل]
لا تتخطَّ حقل التعليق عند «إرسال للمرحلة التالية» حتى يبقى أثر المراجعة.
:::

:::danger[رفع فقط لا يمر بالمراجعة]
إن كان النوع Upload Only فلن يظهر تبويب سير العمل ولن يُرسل للمراجعة. اختر النوع الصحيح قبل الإنشاء.
:::

:::note[الوثيقة المرتبطة تقفل الحقول]
مع `LinkedDocumentId` تُقفل النوع والبادئة والمقاول والمشروع والتخصصات مع لافتة نسخ.
:::
