# فواتير المرتجع

**فاتورة المرتجع (ReturnInvoiceAR)** مستند مرتجع مقابل فاتورة مبيعات. تستخدم نفس نمط رأس الذمم كـ InvoiceAR ثم **Post** و**AddRefund**.

**المسار:** القائمة الجانبية ← المبيعات ← فواتير المرتجع  
**الصفحات:** `/Entities/CRM/ReturnInvoiceAR` · `/Entities/CRM/ReturnInvoiceAR/{رقم}`

## المرتجع مقابل InvoiceAR

| الموضوع | InvoiceAR | ReturnInvoiceAR |
|---|---|---|
| الغرض | فوترة العميل | عكس / إرجاع مقابل فاتورة أصلية |
| الإنشاء المعتاد | من SO أو `/InvoiceAR/new` | من إجراء Return على الفاتورة أو قائمة المرتجع |
| إجراء النقد | **AddPayment** | **AddRefund** |
| الربط | عميل + SO | عميل + فاتورة أصلية |

## القائمة

### الأعمدة (الأهم)

الاسم، الفاتورة الأصلية، العميل، تاريخ الإصدار، الإجمالي، الحالة.

### التصفية

بحث، الحالة، العميل، الفاتورة.

## الحقول الإلزامية

نفس مجموعة رأس الذمم كالفاتورة: العميل، ربط الفاتورة المرتبطة، تاريخ الإصدار، العملة، تاريخ الاستحقاق، طريقة الشحن، السرية، والحالة كما يفرضها النموذج.

## إجراءات دورة الحياة

| الإجراء | الوظيفة |
|---|---|
| **Post** | يرحّل المرتجع |
| **AddRefund** | يعيّن / يسجّل مردودًا |

## التبويبات

التفاصيل، الأنشطة، المرفقات، السجلات، إضافة إلى **LineItems**.

## كيف تعالج مرتجعًا

1. أنشئ من إجراء Return على الفاتورة، أو افتح فواتير المرتجع
2. أكّد العميل والفاتورة الأصلية؛ أكمل الرأس و**LineItems**
3. **Post** عند الجاهزية
4. **AddRefund** لتسوية المرتجع (انظر [مردودات الذمم](/docs/crm/refund-ar))

## أفضل الممارسات

:::tip[ابدأ من الفاتورة الأصلية]
إنشاء المرتجع من InvoiceAR يحافظ على رابط الفاتورة الأصلية صحيحًا.
:::

:::warning[رحّل قبل تسوية المردود]
أكمل وPost المرتجع قبل الاعتماد على AddRefund للتسوية.
:::
