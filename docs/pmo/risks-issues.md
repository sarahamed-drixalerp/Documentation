# المخاطر والمشكلات

المشروع الذي لا يسجّل مخاطره يفاجئ الإدارة عند وقوعها. تبويب **المخاطر والمشكلات** يفصل بين ما قد يحدث وما حدث فعلًا.

**المكان:** عرض 360 ← **المخاطر والمشكلات**

| | المخاطر | المشكلة |
|---|---|---|
| التوقيت | مستقبلية | قائمة الآن |
| السؤال | ماذا لو؟ | ماذا حدث؟ |
| الهدف | تجنب أو تخفيف | حل وإغلاق |

## الحقول المشتركة

| الحقل | الشرح |
|---|---|
| الاسم والوصف | الحدث وأثره |
| النوع | فني أو إداري (أو أنواع مؤسستك) |
| تاريخ الفتح | متى سُجّل |
| الأثر | حجم الضرر إن وقع / الواقع |
| الأهمية / الاستعجال / الشدة | لتحديد أولوية المعالجة |
| استراتيجية التعامل | قبول، تجنب، تخفيف، تحويل… |

## حالات المخاطر

- مفتوحة
- قيد المعالجة
- محلولة

## حالات المشكلات

- مفتوحة
- قيد المعالجة
- محلولة

(قد تظهر تسميات الحالة كما ضبطتها المؤسسة.)

## كيف تدير المخاطر

1. سجّل المخاطر في بداية المشروع لا عند الأزمة
2. عيّن مالكًا لكل مخاطرة عالية
3. راجع المخاطر العالية أسبوعيًا مع الجدول
4. إذا وقعت المخاطرة، أغلقها وأنشئ **مشكلة** مرتبطة بالحدث الفعلي

## كيف تدير المشكلات

1. سجّل المشكلة يوم ظهورها مع الأثر
2. حدّد هل توقف العمل أم يمكن الالتفاف
3. اربطها بطلب تغيير إذا تطلّب الحل تعديل نطاق أو تكلفة أو زمن
4. لا تترك حالة «قيد المعالجة» بلا تاريخ مراجعة

## أفضل الممارسات

:::tip[مخاطرة بلا مالك ليست مخاطرة مُدارة]
إذا لم يظهر اسم مسؤول في المتابعة الأسبوعية، لن تتحرك المعالجة.
:::

:::warning[إخفاء المشكلات لحماية «صورة» المشروع]
المشكلة غير المسجّلة تصل للإدارة متأخرة وبأثر أكبر. السجل هنا للحماية لا للمحاسبة الشخصية.
:::
