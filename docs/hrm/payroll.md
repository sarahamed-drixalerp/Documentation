# مسيرات الرواتب

**مسير الرواتب** هو تشغيل رواتب لفترة محددة في Drixal ERP. تجمع الفترة الموظفين، تحتسب المستحقات والاستقطاعات، ثم تُنشر وتُقفل.

**المسار:** القائمة الجانبية ← الموارد البشرية ← مسيرات الرواتب  
**الصفحات:** `/Entities/HRM/Payroll` · الإنشاء `/Entities/HRM/Payroll/new` · السجل `/Entities/HRM/Payroll/{رقم}`

لا يوجد عرض 360 منفصل؛ صفحة السجل هي مساحة العمل.

## ماذا يفعل مسير الرواتب لأعمالك

- يعرّف فترة الرواتب: الاسم، تاريخ البداية، تاريخ النهاية
- يربط الموظفين بالمسير ويحسب إجمالي المستحقات والاستقطاعات وصافي الدفع
- يوفّر دورة حياة واضحة: معلق ← محتسب ← مكتمل ومقفل
- يمنع التعديل بعد الاحتساب أو النشر حتى تبقى الأرقام موثوقة

## قائمة مسيرات الرواتب

### الأعمدة الافتراضية

- الاسم
- تاريخ البداية
- تاريخ النهاية
- إجمالي المستحقات (TotalEarning)
- إجمالي الاستقطاعات (TotalDeduction)
- صافي الدفع (NetPayment)
- الحالة (Status) بوسم ملون
- إجراءات الصف: تعديل، حذف

### الحالات في القائمة

| الحالة | المعنى |
|---|---|
| **معلق / Pending** | قابل للتعديل؛ عيّن الموظفين ثم احتسب |
| **محتسب / Generated** | الأرقام محسوبة؛ التعديل مقفل؛ يمكن النشر |
| **مكتمل / Completed** | منشور ومقفل نهائيًا |

### التصفية

يمكنك التصفية حسب: الاسم، الحالة، تاريخ البداية، تاريخ النهاية.

## إنشاء مسير رواتب

1. من **مسيرات الرواتب** اضغط **إنشاء مسير رواتب جديد**
2. تُفتح `/Entities/HRM/Payroll/new`
3. عبّئ الاسم وتاريخ البداية وتاريخ النهاية
4. اضبط بيانات الترويسة (النوع / الحالة / السرية / الوصف) عند الحاجة
5. احفظ السجل
6. انتقل إلى تبويب **الموظفين** وعيّن الموظفين
7. نفّذ **احتساب** ثم لاحقًا **نشر** — التفاصيل في [دورة حياة مسير الرواتب](/docs/hrm/payroll-lifecycle)

### الحقول الإلزامية

| الحقل | لماذا هو إلزامي |
|---|---|
| **الاسم** | تعريف فترة الرواتب |
| **تاريخ البداية** | بداية الفترة |
| **تاريخ النهاية** | نهاية الفترة |
| **بيانات الترويسة (نوع / حالة / سرية)** | حوكمة السجل في الترويسة |

## تبويب الموظفين

بعد الحفظ، عيّن الموظفين من تبويب **الموظفين** داخل `/Entities/HRM/Payroll/{رقم}`. بدون موظف واحد على الأقل لن يعمل الاحتساب.

يمكن أيضًا فتح مسيرات الموظف من تبويب الرواتب في [عرض 360 للموظف](/docs/hrm/employee-360).

## القفل بعد الاحتساب أو الإكمال

عندما تكون الحالة **Generated** أو **Completed** يُقفل التعديل على النموذج والمرفقات. راجع الموظفين والمجاميع قبل الاحتساب.

:::danger[بعد الاحتساب أو الإكمال يُقفل التعديل]
لا تعتمد على تعديل لاحق. صحّح التعيين وبنود الراتب قبل الضغط على احتساب.
:::

## أفضل الممارسات

:::tip[أغلق الفترة قبل البدء بالشهر التالي]
أنهِ الاحتساب والنشر لفترة مكتملة قبل إنشاء مسير جديد لنفس المجموعة حتى لا تختلط الأرقام.
:::

:::tip[راجع صافي الدفع قبل النشر]
النشر يقفل المسير كـ Completed. أي تصحيح بعد النشر يتطلب سياسة إدارية خارج التعديل المباشر.
:::
