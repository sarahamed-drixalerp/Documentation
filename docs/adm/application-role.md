# أدوار التطبيق

**دور التطبيق (Application Role)** هو حزمة الصلاحيات التي تُمنح لمستخدمي التطبيق. يحدد الدور ما يمكن رؤيته وتنفيذه على الكيانات، ومستوى سرية البيانات المرتبط بالوصول.

الدور ليس مجرد اسم. هو الرابط بين المستخدم والصلاحيات (Claims) وشجرة الكيانات ومستويات السرية (NCA). بعد الإنشاء تظهر تبويبات الصلاحيات والمستخدمين لإكمال الضبط.

**المسار:** القائمة الجانبية ← الإدارة ← الأدوار  
**الصفحات:** `/Entities/ADM/ApplicationRole` · `/Entities/ADM/ApplicationRole/new` · `/Entities/ADM/ApplicationRole/{رقم}`

## ماذا يفعل الدور لأعمالك

- يعرّف حزمة وصول قابلة لإعادة الاستخدام بدل ضبط كل مستخدم يدويًا
- يربط الصلاحيات بشجرة الكيانات (CAT → الكيان)
- يضبط مستويات سرية البيانات (NCA) على الصلاحيات
- يتيح تعيين المستخدمين أو إزالتهم من تبويب المستخدمين
- يدعم تفعيل الدور أو إيقافه عبر **isActive**

## قائمة الأدوار

### عرض القائمة

الأعمدة الافتراضية:

- الاسم
- إجراءات الصف (مثل التعديل والحذف حسب الصلاحية)

اضغط الاسم لفتح `/Entities/ADM/ApplicationRole/{رقم}`.

### التصفية والبحث

يمكنك التصفية حسب:

- البحث (Search)
- النوع (Type)
- الحالة (Status)

### الإجراءات من القائمة

1. **إنشاء دور جديد** — يفتح `/Entities/ADM/ApplicationRole/new`
2. **تعديل** — يفتح `/Entities/ADM/ApplicationRole/{رقم}`
3. **حذف** — من الترويسة أو القائمة حسب الصلاحية؛ يتطلب تأكيدًا

## إنشاء وتعديل دور

1. من القائمة اضغط الإنشاء، أو افتح سجلًا موجودًا
2. في تبويب **التفاصيل** عبّئ الحقول الإلزامية
3. أضف الوصف ونوع الدور إن لزم، واترك **isActive** مفعّلًا ما لم تقصد إيقاف الدور
4. احفظ
5. بعد الإنشاء افتح تبويب **الصلاحيات** ثم تبويب **المستخدمين**

### الحقول الإلزامية (SaveDetails)

| الحقل | لماذا هو إلزامي |
|---|---|
| **الاسم (name)** | تعريف الدور في النظام |
| **الاسم بالعربية (nameAr)** | الواجهة العربية والتقارير |

### حقول اختيارية

| الحقل | الاستخدام |
|---|---|
| الوصف / الوصف بالعربية | توضيح غرض الدور |
| النوع (type) | تصنيف اختياري للدور |
| **isActive** | تبديل النشاط؛ الافتراضي **true** |

## تبويبات صفحة السجل

على `/Entities/ADM/ApplicationRole/{رقم}`:

| التبويب | متى يظهر / يُستخدم |
|---|---|
| **التفاصيل (Details)** | الإنشاء والتعديل والحقول الأساسية |
| **الصلاحيات (Permission)** | بعد الإنشاء — ضبط Claims على شجرة الكيانات |
| **المستخدمون (Users)** | بعد الإنشاء — تعيين أو إزالة المستخدمين |

من ترويسة السجل يتوفر **حذف الدور (Delete Role)**.

## تبويب الصلاحيات

1. اختر من شجرة **CAT → الكيان**
2. فعّل أو أوقف الـ Claims المتاحة للكيان
3. اضبط مستوى سرية البيانات (NCA) عند الحاجة
4. احفظ قبل مغادرة الصفحة

### Claims الشائعة

| Claim | المعنى |
|---|---|
| GetAll | عرض القائمة |
| GetById | عرض سجل واحد |
| Create | إنشاء |
| Edit | تعديل |
| Delete | حذف |
| 360 | عرض مساحة 360 |
| + صلاحيات خاصة بالكيان | حسب تعريف الكيان |

:::note[علاقات الصلاحيات]
- **GetAll** يستلزم **GetById**
- **360** يستلزم **GetById**
:::

### مستويات سرية البيانات (NCA)

| المستوى | المعنى |
|---|---|
| 1 | عام (Public) |
| 2 | داخلي (Internal) |
| 3 | سري (Confidential) |
| 4 | سري للغاية (Top Secret) |

:::warning[حارس المغادرة بدون حفظ]
إذا غيّرت الصلاحيات وحاولت مغادرة التبويب دون حفظ، يمنعك النظام أو ينبّهك حتى تحفظ أو تلغي التغييرات.
:::

## تبويب المستخدمين

بعد إنشاء الدور:

- عيّن مستخدمين للدور أو أزلهم
- تعرض القائمة عادةً حالة **نشط / غير نشط**، و**البريد**، و**المسمى الوظيفي**

## أفضل الممارسات

:::tip[أكمل الصلاحيات قبل تسليم الدور]
أنشئ الدور، اضبط Claims ومستويات NCA، ثم عيّن المستخدمين. دور بلا صلاحيات لا يمنح وصولًا فعّالًا.
:::

:::warning[احذف الدور بحذر]
حذف الدور من الترويسة يزيل الحزمة. راجع المستخدمين المعيّنين أولًا، أو أوقف **isActive** إن أردت تعطيلًا مؤقتًا.
:::

:::note[التبويبات التابعة بعد الإنشاء]
تبويبا **الصلاحيات** و**المستخدمين** يظهران بعد إنشاء السجل، وليس قبل أول حفظ.
:::
