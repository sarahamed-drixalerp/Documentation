# Create a New Project

Creating a project turns an agreement or initiative into a record the team can work from. After you save it, the project number appears and you can open the 360 workspace to add the scope and schedule.

## How to Create a Project

1. From **Projects**, select **Create New Project**
2. The Standard View opens with the title “Create New Project”
3. Complete the required fields in the header and General Information section
4. Add governance details and settings if they are already known
5. Select **Save Changes**
6. After saving, you can **Post** the project to apply the update shown on the page while keeping the record editable

:::tip[You can create a project from an agreement]
If an agreement exists with the customer, link it during creation. Some organizations start from the agreement and convert it into a project so the contract and execution remain connected.
:::

## Required Fields

The project cannot be saved without these fields:

| Field | Why it is required |
|---|---|
| **Name (English)** | Operational record name and search value |
| **Project Manager** | Operational accountability |
| **Type** | Project classification for reporting |
| **Status** | Starting point in the lifecycle, usually Active |
| **Confidentiality Level** | Determines who can view the record |
| **Start Date** | Beginning of the plan |
| **End Date** | Must be the same as or later than the start date |

The **Arabic Name** field is recommended for Arabic interfaces and local reports, but it is not required.

## Information to Enter on Day One

| Field | Benefit |
|---|---|
| Customer | Connects billing and commercial reports |
| Account Manager | Bridges sales and account management |
| Team Size | Provides an initial planning indicator |
| Value and Currency | Establish the basis for budgeting and billing |
| Description in both languages | Gives new team members context without requiring them to ask the project manager |
| Agreement / Program / Portfolio | Supports management reporting |
| PMO Auditor | Establishes the governance path |

## Saving and Posting

| Button | What it does |
|---|---|
| **Save Changes** | Stores the current data |
| **Post** | Saves and updates the project with the displayed data while keeping the record editable |

When you post, a dialog explains that:

- Changes are saved
- The project is updated with the displayed data
- The project remains editable after posting

:::note[Posting here is not an accounting close]
Posting a project applies the current update and does not prevent later edits. To close the work, use Complete or Terminate.
:::

## Common Creation Errors

- End date is earlier than the start date
- Project Manager is left blank
- The project uses an internal name the customer does not recognize, making it difficult to find later
- Confidentiality Level is omitted, causing a “This field is required” error

## Immediately After Saving

1. Review the serial number in the header
2. Go to the [360 View](/docs/pmo/workspace-360)
3. Add [Project Line Items](/docs/pmo/line-items) if the project has a priced scope
4. Add [Stakeholders](/docs/pmo/stakeholders)
5. Build the [Schedule](/docs/pmo/schedule)

## Best Practices

:::tip[Create the project before the team starts logging hours]
Hours logged outside an approved project are excluded from cost, progress, and timesheet approval.
:::

:::warning[Do not use one project for multiple customers]
Each customer and contractual commitment should have a separate project record, even when the teams are similar.
:::
