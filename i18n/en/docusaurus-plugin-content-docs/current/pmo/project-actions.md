# Project Actions

Formal actions change the project lifecycle in a traceable way, unlike manually editing the status badge. The buttons appear in the headers of both the Standard View and 360 View.

## Save and Post

| Action | When to Use It |
|---|---|
| **Save Changes** | After editing fields |
| **Post** | To confirm the displayed update while keeping the project editable |

Posting displays a dialog explaining that the data will be saved, the record updated, and the project kept open for editing.

## Pause

Pauses work without closing the project. This action appears when the project is neither completed nor already paused.

**When to use it**

- A lengthy wait for client approval
- A temporary funding shortfall
- A known external blocker that is expected to be removed

After pausing, the **Resume** button appears so you can return the project to active status.

## Resume

Returns a paused project to active status so the team can log hours and update progress.

Review dates and risks before resuming: is the plan still valid, or is a change request required?

## Complete

Closes the project successfully. Do not use this action if significant scope remains undelivered or a Certificate of Completion is missing.

Before completing the project, confirm that:

- Deliverables are complete
- Billable milestones are closed or explained
- Lessons learned are recorded
- Timesheets are clearly approved or rejected

## Terminate

Closes the project without completion and requires a termination reason. Use it for a contractual cancellation or a permanent stop that is not expected to resume.

:::danger[Termination is a management decision]
Do not terminate a project with open invoices or a delivery dispute before finance and the client have reached an agreement. The written reason will appear in the audit trail.
:::

## Timesheet Approval

Opens a review of the team's pending hours for this project. See [Timesheet Approval](/docs/pmo/timesheet) for details.

## Activation and Confidentiality

- **Enabled / Disabled**: hides the project from daily operations without deleting it
- **Confidentiality Level**: determines who can view the record

Some users have view-only access and cannot perform actions.

## Best Practices

:::tip[Change status through an action, not only the badge]
The action preserves context, such as the termination reason. Changing status only from the dropdown may leave reports without an explanation.
:::

:::note[A completed project cannot be resumed with the same button]
The Resume flow applies to paused projects. A completed project is reopened through an administrative policy if your organization permits it.
:::
