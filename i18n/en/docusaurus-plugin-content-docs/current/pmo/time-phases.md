# Phases and Milestones

The **Time** tab divides the project duration into phases and milestones that clients and management can review without navigating hundreds of tasks.

**Location:** 360 View ← **Time** ← **Phase** or **Milestone**

The practical difference:

- A **phase** is a period with a start and end date (such as design, procurement, or operations).
- A **milestone** is a due date for an important outcome and may be billable.

## Phases

| Field | Description |
|---|---|
| Name / Arabic Name | The phase name |
| Project | Populated automatically from the parent record |
| Start Date / End Date | The phase boundaries |

Use phases to summarize the work for senior management: where are we in the project journey? Do not use them to duplicate the entire Gantt structure.

**Example**

1. Preparation and mobilization
2. Execution
3. Testing and handover
4. Initial support

## Milestones

| Field | Description |
|---|---|
| Name | What will be completed on this date |
| Milestone Date | The due date |
| Billable | Whether reaching the milestone triggers a financial claim |

Billable milestones must align with the [Billing Plan](/docs/pmo/financials). If a “Site Handover” milestone is tied to a payment, mark it as billable and create a corresponding billing-plan item.

## How to Use the Tab

1. Define 3 to 6 phases that cover the full duration without major gaps.
2. Add at least one milestone at the end of each phase.
3. Show client milestones (handover, approval, and payment) here even if they also appear in the Gantt chart.
4. Review overdue milestones weekly.

## Best Practices

:::tip[Milestones are for the client; tasks are for the team]
Do not use “Write weekly report” as a milestone. A milestone is an event that matters to the client, management, or billing.
:::

:::warning[A phase without dates does not support reporting]
If the phase dates are left blank, the timeline in the 360 sidebar will not provide a useful phase-level view.
:::
