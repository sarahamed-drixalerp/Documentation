# Project Management Office

The Project Management Office in Drixal ERP is the operations hub for projects across the organization. It brings portfolios, programmes, agreements, and projects into one structure, then opens a full workspace for each project: scope, schedule, team, financials, risks, delivery proofs, and governance.

Without this office, projects stay scattered: a contract in email, a schedule in a spreadsheet, costs in accounting, and deliverables in folders. Inside Drixal, a project becomes a live record connected to the customer, contract, sales orders, invoices, and team hours.

## What the office does for your business

- Unifies the working language: Portfolio → Programme → Agreement → Project
- Gives the project manager one screen for progress, cost, and risk
- Lets leadership see the full portfolio instead of asking each project manager separately
- Links execution to billing: billable milestones, billing plan, customer invoice, delivery proof

## Hierarchy

```text
Portfolio
  └── Programme
        └── Agreement
              └── Project
                    ├── Line items
                    ├── Scope and schedule
                    ├── Financials and delivery
                    └── Governance and team
```

| Level | Purpose |
|---|---|
| **Portfolio** | Strategic grouping (for example infrastructure in Riyadh) |
| **Programme** | Related projects under one shared goal |
| **Agreement** | Contractual frame with the customer; can be converted into a project |
| **Project** | Day-to-day execution unit: team, schedule, cost, delivery |

You can open a project directly without a portfolio or programme when the work is simple. Linking is optional, but important for management reporting.

## Where to find it in the system

From the side menu choose **Project Management Office**, then:

- Dashboard
- Agreements
- Portfolios
- Programmes
- **Projects** ← the focus of this guide
- Task priorities / task size / task complexity (setup data)

| Role | Daily use |
|---|---|
| PMO manager | Governance, audit, project statuses, approvals |
| Project manager | Create projects and run the 360 workspace |
| Account manager | Link customer and agreement; follow billing |
| PMO auditor | Supervise procedure compliance |

## How the project guide is organized

1. Understand the project, its types, and statuses
2. Work with the list (search, filter, create)
3. Fill details, governance, and settings
4. Use the 360 workspace and every tab
5. Formal actions: pause, resume, complete, terminate, approve timesheets
6. Insights and glossary

## Best practices

:::tip[Do not start the schedule before the base record]
Create the project first with the required fields, then add line items, scope, and schedule. A schedule without a project linked to customer and dates becomes an orphaned plan.
:::

:::warning[Permissions show or hide data]
Some users see the project as read-only, and some financial fields may be hidden. If you see “Restricted information”, that is a permissions setting—not a defect.
:::
